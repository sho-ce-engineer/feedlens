# ADR-0004: ダイジェストを廃止し、Hot以外・上限超過・会員限定・判定失敗は通知しない

- 状態: 採用(PR #54 でマージ済み)
- 日付: 2026-11-28

## 背景

これまでは、Hot にならなかった記事、判定に失敗した記事、会員限定と判定された記事を、タイトルとリンクだけのダイジェストにまとめて送っていた。ダイジェストには件数の上限がなく、記事が多すぎて読めなくなっている状況の一因と見ている(件数の内訳は、実際のログでは確かめていない)。

## 決定

- ダイジェスト(`notifyDigest`・`buildDigestMessages`)を廃止する。
- 次の記事は、通知しない。
  - Hot でない記事
  - 上限(ADR-0003)に入らなかった記事
  - 会員限定と判定された記事: 破棄する。要約の時点で分かるので、破棄した分は、順位が次の候補で枠を埋める。
  - 判定に失敗した記事: エラーとして記録し、実行結果サマリに「判定失敗」の件数を出す。
- `DISCORD_DIGEST_WEBHOOK_URL` を、アプリ本体では使わない(必須チェックも外した)。

## 検討した代替案

- 判定に失敗した記事を、従来どおりダイジェストに回す: ダイジェストを廃止するので、成り立たない。通知から漏らさないための仕組みだったが、取りこぼしは件数で把握する形にした。
- 会員限定の記事に印を付けて通知する: 会員限定の記事には価値がないという判断で、採らなかった。

## 結果

- 通知は、点数順の上位だけになる。
- 無料枠のレート制限が多い日は、判定に失敗した記事の取りこぼしが増える。サマリの「判定失敗」で気づける。
- `DISCORD_LOG_WEBHOOK_URL` が未設定のときの、サマリの送り先が、ダイジェスト用チャンネルから Hot のチャンネルに変わる。
- `.github/` のワークフローは、この変更では触っていない。失敗通知は、`DISCORD_LOG_WEBHOOK_URL` が未設定のとき、今もダイジェスト用の Webhook を参照する。そのため、`DISCORD_DIGEST_WEBHOOK_URL` の Secret は残してある。

## 未確認と見直しの条件

- 判定失敗の件数が実際にどれくらいになるかは、まだ見ていない。多い日が続くなら、再試行の仕組みを検討する。
