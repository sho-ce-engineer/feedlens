# ADR-0006: URLを正規化して、同一実行内の重複記事を除外する

- 状態: 採用(PR #53 でマージ済み)
- 日付: 2026-11-28

## 背景

同じ記事が何度も出る。計測用のクエリ違いや、集約系の媒体による再掲で、同じページの URL が文字列として別物になり、重複と判定できなかった。issue #20 の前半にあたる。

## 決定

- URL を正規化して、同じ文字列になった記事を1件にまとめる(`normalizeUrl`、`dedupeArticles`)。
- 正規化の内容:
  - 除去する: `utm_*`、`fbclid`、`gclid`、`yclid`、`mc_cid`、`mc_eid`、`igshid`、フラグメント、末尾スラッシュ(ルートの `/` は残す)
  - 揃える: ホスト名の小文字化、クエリの並び順
  - 残す: 上記以外のクエリ。`?id=123` のように、記事の識別そのものになっているものがあるため
  - URL として解釈できない文字列は、元のまま比べる
- 重複していたときは、フィード順で最初に現れた記事を残す。
- 適用する位置は、直近24時間の絞り込み(`filterRecent`)の直後で、判定の前。同じ記事を何度も判定する、Gemini の無駄な呼び出しをなくすため。
- 対象は、同一実行内の重複だけ。

## 検討した代替案

- クエリを全部消す: 記事の識別になっているクエリを消すと、別の記事を同じ記事として落とす。
- `www.` の有無と `http` / `https` を揃える: 誤判定のリスクは低いと思われるが、issue の範囲外として入れていない。
- 日をまたぐ重複の排除: 既読管理が要る。別の issue(#24)。
- 同一トピックの記事を束ねる: 別の施策(#20 の後半)。まだ決めていない。

## 結果

- 集約系の媒体のフィードが、元の媒体より先に来ると、集約側の記事が残る。残す記事は、フィードの並び順(`feeds.json`)に依存する。
- 実行結果サマリに「重複除外: N件」が出る。

## 未確認と見直しの条件

- 実際のフィードで、何件が落ちるかは、まだ見ていない。URL が完全に一致する重複が少なく、落ちるのが計測パラメータ付きの分だけの場合、効果は小さい。サマリの件数で確かめる。
