# ADR-0001: ADRを導入し、設計判断をコメントではなくADRに書く

- 状態: 採用
- 日付: 2026-11-28

## 背景

設計判断の理由を、コードのコメントに書いていた。コメントは、コードを読めば分かる説明や、判断の経緯とずれたものになりやすい。PR #54 のレビューで、「不要なコメントは載せない。設計判断につながる項目はADRにする」という指摘があった。

## 決定

- 設計判断は、`docs/adr/` に1判断1ファイルで書く。書式は [README](./README.md) に従う。
- コードのコメントには、「コードを読めば分かること」と「設計判断に係ること」を書かない。残すのは、コードから読めない事実(値の向き、外部サービスの制約への注意など)だけ。

## 検討した代替案

- 設計判断を README に書き足す: 判断ごとの経緯と、置き換えの履歴を残しにくい。
- 設計判断をコメントに書き続ける: 上に書いた理由で採らない。

## 結果

- 判断の理由は、ADRを読めば分かる。コードは、何をしているかに集中できる。
- 既存のコメントには、設計判断にあたるものが残っている可能性がある。この決定に合わせた整理は、このADRの導入では行っていない。
